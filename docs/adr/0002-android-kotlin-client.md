# Android-клиент на Kotlin, список внутри версии

Справочник читали клиентом Expo: собирались Android и web, iOS в конфигурации не было, список обновлялся с выкладки Expo web. Решили оставить один Android-клиент в этом репозитории — Kotlin и Jetpack Compose, `applicationId` `com.fuflomycin_rn`, пол API 24. Список и кадры компилирует нынешний `list-build` и они входят в версию; по сети клиент их не обновляет, отсутствующий кадр роняет сборку. Так сделано, потому что отдельная файловая выкладка после отказа от web-клиента стала бы публичным JSON-кормом, а контракт карточек уже зафиксирован `list-build`. Светлая тема сохраняет нынешний вид, тёмная следует системе, dynamic color выключен, чтобы ярлыки оставались метками вердикта.

## Considered Options

- Оставить Expo и публиковать web вместе с Android.
- Compose Multiplatform, чтобы вернуть iOS, которого в конфигурации не было.
- Суточное обновление со статического хоста (GitHub Pages этого репозитория или файлы без экранов на прежнем origin).
- Переписать компилятор карточек на Kotlin.

## Consequences

- Новая карточка доходит до человека только с новой версией из Play, не на следующий день у уже установленной.
- Старый кэш списка не читается: виден список этой версии.
- Механизм пола галереи из ADR-0001 снят: Metro-карта `require()` и запасной `https://<origin>/img/<имя>` больше не канон.
