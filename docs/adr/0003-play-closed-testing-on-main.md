# Закрытое тестирование при пуше в main

Справочник собирает GitHub Actions. Пуш в ветку, кроме `main`, кладёт подписанный release-APK в артефакты и публикует его публичным prerelease `fuflomycin-<versionName>-<короткий sha>` с тегом `apk-<sha>`: артефакт Actions протухает, а сборку ветки нужно оставить. Текст prerelease — первая строка сообщения коммита. В Play эта сборка не уходит. Пуш в `main` собирает AAB и выкладывает его на дорожку закрытого тестирования (`alpha`) со статусом `completed`. `versionCode` этой выкладки — наибольший код уже в Play плюс один, в git он не пишется; `versionName` остаётся строкой из Gradle. В прод Actions не публикует: туда релиз переносят руками, поэтому новая карточка доходит до тестировщиков дорожки с этим пушем, а до человека на проде — только после переноса. Сервисный аккаунт `fuflomycin` в проекте `fuflomycin-android` ролей Cloud не имеет и в Play умеет только выпуск на тестовые дорожки, поэтому тем же ключом перенос в прод не сделать.

## Considered Options

- Собирать APK и на `main`, вместе с AAB.
- Брать `versionCode` из числа коммитов или из номера прогона Actions.
- Выкладывать на внутреннее тестирование или сразу в прод.
- Оставлять APK только артефактом Actions.

## Consequences

- Пока сервисный аккаунт не приглашён к `com.fuflomycin_rn`, выкладка с `main` получает отказ Play.
- APK с ветки носит `versionCode` из Gradle, чтобы не оказаться выше линии Play: иначе обновление с закрытого тестирования поверх такого APK не встанет.
- На каждый пуш не в `main` появляется публичный тег и prerelease: подписанный APK этой сборки может скачать кто угодно. Артефакт Actions при этом остаётся.
